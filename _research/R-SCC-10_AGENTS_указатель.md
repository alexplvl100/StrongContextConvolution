# R-SCC-10: AGENTS.md как указатель на методологии — проверено

**Дата:** 2026-10-28
**Вопрос заказчика:** можно ли в `AGENTS.md` поместить методологии и их
назначение, попросить агента сначала обращаться к методологии, указать правила
статуса (гейт) — чтобы **не просить каждый раз** ознакомиться?
**Метод:** разбор кода `dsh-agent-instructions` + **эмпирическая проверка** в
изолированном `DSH_HOME` (`/tmp/scc_gate_test`, живой `~/.dsh` не тронут)

---

| Вопрос | Ответ | Проверено |
|---|---|---|
| Поместятся ли методологии целиком? | **НЕТ**: 117 565 байт против бюджета 65 536 (×1,8) | измерено |

**Итог: идея работает.** Указатель помещается, автоматически подаётся,
автоматически обновляется и автоматически восстанавливается после компакции.
Просить ознакомиться каждый раз **не нужно**.

## 1. Полные методологии не помещаются

| Файл | Байт |
|---|---|
| `METHODOLOGY.md` | 7 713 |
| `METHODOLOGY_CORE.md` | 14 447 |
| `METHODOLOGY_MEMORY.md` | 25 213 |
| `METHODOLOGY_CAS.md` | 23 122 |
| `METHODOLOGY_HEAD.md` | 36 120 |
| `METHODOLOGY_STATE.md` | 10 950 |
| **Итого 6 методологий** | **117 565** |
| **Бюджет `maxBytes`** | **65 536** |
| **Превышение** | **×1,8** |

**Почему это важнее, чем просто «не влезет».** Механизм не отвергает
превышение — он **молча усекает**:

> «Rendering keeps the most specific files first: it **drops whole broader files
> before truncating** the most-specific file, and emits a visible
> `Workspace instruction budget ...` notice naming the omitted and truncated
> paths.»

То есть при попытке засунуть методологии целиком **часть документов исчезла
бы**, и агент читал бы неполную методологию, считая её полной. Это **опаснее**,
чем отсутствие указателя.

**Вывод: тела методологий в `AGENTS.md` класть нельзя.** Только указатель.

## 2. Указатель помещается с большим запасом

Прототип (78 строк, собран и проверен):

| | Байт | Строк | Доля бюджета |
|---|---|---|---|
| **Указатель** | **5 215** | 78 | **8,0 %** |
| Запас | 60 321 | — | 92,0 % |

**Что вошло в указатель:**

1. **Назначение проекта** — что такое SCC, что разработка идёт по методологиям.
2. **Порядок работы** — «при любом вопросе о поведении системы СНАЧАЛА прочитай
   методологию, потом действуй; не полагайся на память».
3. **Таблица «где что лежит»** — документ, за что отвечает, **когда читать**.
4. **ГЕЙТ СОСТОЯНИЯ** — команда проверки, таблица кодов 0/1/2, четыре правила.
5. **Восемь инвариантов** — сжато, со ссылкой на полный текст.
6. **Порядок контекста** — `[HEAD] + [средняя] + [короткая]`.
7. **Чего не делать** — четыре запрета.

**Запас 60 КБ** позволяет добавить соглашения проекта, команды сборки, структуру
каталогов — то, что сейчас приходится объяснять в каждом диалоге.

## 3. Проверка: агент читает указатель и слушается

Изолированный прогон с `AGENTS.md` в `$DSH_HOME`:

> **Вопрос:** «Одним предложением: какое состояние методологии разрешает
> реализацию, а какое запрещает? Ответь по системному контексту, файлы не читай.»
>
> **Ответ:** «Из системного контекста: состояние `ПРИНЯТ` (гейт возвращает 0)
> разрешает реализацию, а `В_РАБОТЕ` (гейт возвращает 1) запрещает её
> полностью — при этом отсутствие состояния (код 2) не является разрешением,
> а неизвестностью.»

**Верно, без чтения файлов.** В рассуждении видно источник: «From the AGENTS.md
instructions: ПРИНЯТ (all methodologies accepted) → code 0 → implementation
allowed». То есть указатель **прочитан и применён**.

**Второй прогон** добавил детали, которых в указателе прототипа **не было
дословно** — модель сама достроила:

> «**`ПРИНЯТ` — это тоже не полная свобода.** Реализовывать можно, но **нельзя
> править тело** методологии без разрешения пользователя; разрешено обновлять
> только блок `**Реализация:**`.»

Это ожидаемо: указатель задаёт **рамку**, а детали агент берёт из документов.

## 4. ГЛАВНОЕ: переживёт ли `AGENTS.md` компакцию

Это был **основной риск идеи**. Проверен эмпирически.

### 4.1. Риск был реальным

`AGENTS.md` подаётся как **`user/message`**, а не как `system/message`:

```json
{"type":"user/message","seq":9,"data":{
  "source":{"kind":"agent-instructions","form":"instructions","baseline":true},
  "message":{"content":[{"type":"text","text":"<system-reminder>..."}]}}}
```

Компакция **не затеняет только `system/message`** на позиции 0:

> «Every selected range starts at the first surface node that is not a
> `system/message`, so a system prompt at surface node 0 is never shadowed.»

Значит `user/message` с инструкциями **попадает в диапазон затенения**. В моей
рабочей сессии компакция №1 началась ровно с **seq 8** — первого `user/message`.

### 4.2. Проверка в изоляции: компакция затенила AGENTS.md

Сценарий: `thresholdRatio: 0.001`, `retainRatio: 0.0005`, `maxTokens: 8192`.

Результат по журналу:

```
compaction/summary seq=86 range={'start': 8, 'end': 44}
```

**Диапазон `8..44` включает seq 9 — это и есть `AGENTS.md`:**

```
seq  8: user/message source.kind=user              71 симв
seq  9: user/message source.kind=agent-instructions 3490 симв  <- ЗАТЕНЁН
seq 10: user/message source.kind=runtime-context    563 симв
seq 16: assistant/message                          2193 симв
```

### 4.3. Плагин переинжектировал указатель автоматически

**Найдено в журнале после компакции:**

```
seq 95: user/message source.kind=agent-instructions form=instructions baseline=True 3490 симв
```

**Указатель вернулся сам, без вмешательства.** Механизм — в коде плагина
(`dsh-agent-instructions/lib/index.js`):

```js
const syncInbox = (agent, claimed, desired) => {
  const alreadySupplied = desired !== void 0 && (
    claimed.some((message) => sameContextPayload(message, desired)) ||
    agent.session.surface.nodes.some((seq) => {          // <- проверка SURFACE
      const event = agent.session.eventAt(seq);
      return event?.type === "user/message" && sameContextPayload(event.data, desired);
    }));
  if (desired === void 0 || alreadySupplied) { ... return; }   // уже виден -> ничего
  ...                                                          // затенён -> добавить
};
```

И подписка на **каждый шаг**:

```js
ctx.on("agent/pre-step", async ({ agent, messages, step, signal }, next) => {
  const decision = await next();
  ...
  const desired = await compose(agent, signal, messages, pending);
  if (decision.messages.some((message) => sameContextPayload(message, desired))) return decision;
  // иначе вставляет заново
  return { ...decision, messages: entered };
});
```

**Ключ:** `alreadySupplied` проверяет **живую поверхность** (`surface.nodes`), а не
историю. Затенённый узел исчезает из поверхности → проверка не находит → baseline
**добавляется заново**.

### 4.4. Финальная проверка: агент помнит гейт после компакции

После двух компакций — прогон в ту же сессию:

> **Вопрос:** «Какое состояние методологии запрещает реализацию и какой код
> возврата у гейта? Коротко.»
>
> **Ответ:** таблица кодов `0` / `1` / `2` с верными значениями, затем:
> «Проверка сейчас (`cd /tmp/scc_v23 && python3 _engine/tools/check_state.py
> --gate`): код `0`, все шесть методологий `ПРИНЯТ`.»

**Агент не только воспроизвёл гейт, но и сам запустил проверку** — то есть
указатель работает как задумано: он ведёт к действию, а не просто информирует.

## 5. Обновление при изменении файлов

Механизм есть, с явным текстом для модели:

```js
function changedSectionText(item) {
  if (change.action === "set") return additionalSectionText(file);
  if (change.action === "remove") return `Instructions removed: ${change.path}
    The previously loaded instructions from this file no longer apply.`;
  return [`Updated instructions from: ${change.path}`, "",
    "This file changed after it was loaded. Use the following content instead of
     the previously loaded instructions from this file.", "", file.content].join("\n");
}
```

**Когда перечитывается:**

| Событие | Поведение |
|---|---|
| Первый запрос | загружается полный baseline |
| `read`/`write`/`edit` в **глубокий** каталог | подхватывается вложенный `AGENTS.md` |
| Файл изменился | приходит блок «Updated instructions from: …» |
| Файл исчез | «Instructions removed: …» |
| Resume сессии | baseline сверяется заново |

**Непрерывного слежения нет** — «It does not watch external edits continuously».
Изменение подхватится при следующей файловой операции или resume.

**Это отвечает на «методологии динамические»:** правишь `AGENTS.md` — агент
видит новую версию **без перезапуска**, при следующей операции с файлами.
Причём старый baseline **заменяется**, а не копится («replaces all earlier
workspace instruction baselines»).

## 6. Цена решения

| | Токенов | Доля окна 1M |
|---|---|---|
| Указатель (5 215 байт ≈ 3 490 симв) | **~870** | **0,09 %** |
| Для сравнения: системный промт | 1 405 | 0,14 % |
| Для сравнения: 31 схема инструментов | 7 138 | 0,71 % |

**Указатель дешевле системного промта в 1,6 раза.** При переинжекции после
компакции он добавляется заново, но старая копия при этом затенена — в контексте
всегда **ровно одна копия**.

При 35 компакциях на 10 млн токенов переинжекция стоит ~30 000 токенов — это
**3 % от объёма одной компакции**.

## 7. Ограничения проверки

1. **Один прогон в изоляции.** Компакция сработала дважды, переинжекция
   зафиксирована один раз. Повторяемость не измерялась.
2. **Проверен указатель, а не полный `AGENTS.md` проекта.** Содержание прототипа
   — 78 строк; как поведёт себя файл на 60 КБ, не проверялось.
3. **`thresholdRatio: 0.001` — искусственный порог** для быстрого срабатывания.
   На штатном `0.8` компакция происходит реже, но механизм тот же.
4. **Изоляция не переняла ключ провайдера** — потребовалась правка
   изолированного профиля. Живой профиль при этом не тронут (проверено: mtime
   `2026-10-25 20:28:15` не изменился, GUI отвечает HTTP 401).
5. **Не проверено поведение при превышении бюджета на реальном файле.**
   Усечение описано в README, но наблюдать его не довелось.

## 8. Что предлагается сделать

**Создать `AGENTS.md` в корне проекта** (`<проект>/AGENTS.md`)
с указателем из §2. Это:

* снимет необходимость просить ознакомиться с методологиями в каждом диалоге;
* даст агенту гейт состояний **до** первой правки;
* займёт 0,09 % контекста;
* автоматически обновится при правке файла;
* автоматически восстановится после компакции.

**Чего делать НЕ нужно:** класть в `AGENTS.md` тела методологий — превышение
бюджета в 1,8 раза приведёт к **молчаливому усечению**, и агент будет читать
неполный документ как полный.
