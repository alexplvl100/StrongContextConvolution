# plugin — каркас движка компакции SCC для DSH

Материалы для подключения SCC к DeepSeek Harness **без затрагивания рабочей
конфигурации**. Описание метода — в [`../ROLLOUT.md`](../ROLLOUT.md).

| Файл | Что это |
|---|---|
| [`index.js`](index.js) | каркас плагина: форма модуля, точки входа, регистрация |
| [`method.patch.yml`](method.patch.yml) | патч: отключить штатную компакцию, включить SCC |
| [`isolated_run.sh`](isolated_run.sh) | запуск в отдельном `DSH_HOME` — механизм безопасности |

## Статус: каркас, не реализация

**Что работает:**

* изоляция через `DSH_HOME` — проверена полным прогоном с ответом модели;
* патч применяется без предупреждений: штатная компакция отключена, наша строка
  в дереве;
* плагин активируется (нет `pending` для него самого).

**Что не реализовано:**

* `compactIfNeeded` не считает порог и возвращает `null`;
* `compactRegion` бросает исключение;
* связка «сессия → поток событий → ядро SCC → поверхностная замена» отсутствует;
* сервис `compaction` не регистрируется, поэтому `/compact` не активируется.

## Как запускать

```bash
# 1. окружение (создаётся в /tmp, рабочая конфигурация не участвует)
./isolated_run.sh setup

# 2. посмотреть собранную конфигурацию, НЕ запуская
./isolated_run.sh dump | grep -A1 -E 'compaction-basic|scc-compaction'

# 3. прогон
export ROUTERAI_API_KEY=...
./isolated_run.sh run "проверка"

# 4. убедиться, что рабочая конфигурация цела
./isolated_run.sh check

# 5. полный откат
./isolated_run.sh clean
```

Переменные: `SCC_WORK` (каталог окружения, по умолчанию `/tmp/scc_iso`),
`SCC_PROFILE` (имя профиля, по умолчанию `scc-test`).

## Защита от порчи рабочего развёртывания

Скрипт **отказывается работать**, если окружение указывает внутрь рабочего
`DSH_HOME` или если рабочая конфигурация уже нарушена:

```
НАРУШЕНИЕ: WORK (~/.dsh/profiles/web/sub) указывает внутрь рабочего home
(~/.dsh). Это остановило бы исследования
```

`check` показывает дату изменения рабочего патча и код ответа GUI. Дата обязана
оставаться прежней.

## Почему `headless`, а не `web`

В профиле `headless` строка `compaction-basic` лежит **на верхнем уровне**
дерева и адресуется патчем по `id`. В `web` она спрятана **внутри пресета**
`standard`, и патч до неё не достаёт (`entry not found`).

Разработка ведётся там, где точка подключения открыта. Перенос на `web` —
отдельная задача (см. `../ROLLOUT.md` §8.3).

## Что нужно сделать дальше

1. **Зарегистрировать сервис `compaction`** — без него `/compact` не работает
   (`pending (waiting for service: compaction)`).
2. **Реализовать `compactIfNeeded`** — порог, выбор диапазона, исключение уже
   свёрнутого ядра.
3. **Реализовать поверхностную замену** — с проверкой баланса tool-пар.
4. **Связать с ядром SCC** — через stdin/stdout, без записи на диск (в режиме
   поставки запись запрещена, см. раздел исследований).
