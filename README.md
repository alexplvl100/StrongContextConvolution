# StrongContextConvolution

**SCC (Strong Context Convolution)** — свёртка контекста агента без потери ядра.

Обычная компакция заменяет историю пересказом, и каждый пересказ теряет детали.
Замерено на живой сессии (83 компакции, 114 ходов):

```
фактов в 1-й сводке:        129
к 41-й сводке:                1  (1 %)
к 83-й сводке:                0  (0 %)
```

SCC делает иначе: свёрнутое **помечается и больше не пересматривается**.
Повторная свёртка касается только свежей части, ядро переносится дословно.

---

## Система

**Два канала.** В харнессе разделены системный контекст (роль, правила) и
юзерконтекст (диалог). Через ядро проходит **только юзерконтекст**; системный
контекст идёт в HEAD напрямую. Разделение — на конвертере журнала, то есть на
входе: если роль попадёт в поток, ядро её сожмёт, и отменить это будет нечем.

**HEAD** — служебный раздел в начале контекста: роль, инструкция Архивариуса,
инструкция CAS. Не сжимается, не обрабатывается CAS, не уходит в архив
(инвариант 8).

**Три уровня памяти:**

| Уровень | Что это | В контексте |
|---|---|---|
| **Короткая** | несжатый диалог | целиком |
| **Средняя** | стак сжатых чанков | стак |
| **Долгая** | архив чанков | только инструкция; содержимое — через Архивариуса |

Контекст: `[HEAD] + [средняя] + [короткая]`. При выносе в архив он
**уменьшается**, хотя диалог растёт. Перехода «долгая → средняя» нет.

**Точные данные — напрямую, минуя Архивариус.** Ссылка `CAS?{8-64 hex}?`
разрешается вызовом функции. Архивариус — агент с LLM, а генерация
пересказывает: путь стал бы «похожим». Точные данные обязаны возвращаться
дословно.

**Ядро — три прохода.** I: свёртка смысла. II: точные данные по событиям.
III: мерж. Модель не может одновременно сжимать смысл и копировать значения —
на журнале T2 один проход дал **0 значений из 9 182**.

**Пороги выводятся из рабочей зоны**, не задаются произвольно:

```
T = (Z − HEAD)·r/(r + K + 1) − step      порог сжатия
T_arch = K·c + c/2                        порог архивации
```

При фиксированном пороге память вырождается: проверено симуляцией
([`simulate_memory.py`](_engine/tools/simulate_memory.py)) — режим A душит
короткую память, B переполняет зону, устойчив только C.

## Запуск

```bash
python3 _test/run_all.py                              # все тесты, сводка
python3 _engine/tools/check_state.py --gate           # 0 = можно реализовывать
python3 _engine/tools/measure_memory.py --window 262144 --steps 3000
python3 _engine/tools/simulate_memory.py              # устойчивость порогов
```

Тесты модель **не вызывают**: всё, что требует сети, вынесено в `_research/`.

## ABC: нужен ли SCC

Прямой эксперимент: один журнал (**3 199 событий**, 51 365 токенов, **1 200
непредсказуемых точных значений**), три условия, замер по **точности ответа**.

| Условие | Что видит модель | Точность |
|---|---|---|
| **A** штатная компакция | сводка, оригинала нет | **8/1200 (0,7 %)** |
| **B** SCC | артефакт свёртки | **201/1200 (16,8 %)** |
| **C** компакция + поиск | сводка + поиск по журналу | **524/1200 (43,7 %)** |

**Что это значит.**

1. **Гипотеза подтверждена:** штатная компакция теряет точные данные
   **почти полностью** — 0,7 %. Сводка вышла 2 676 символов при лимите 16 000
   токенов, то есть **не была усечена**: модель **осознанно** заменила значения
   обобщениями, хотя промт требует их сохранять.
2. **SCC лучше компакции в 24 раза** (16,8 % против 0,7 %).
3. **Но поиск лучше SCC в 2,6 раза.** Отдельный механизм свёртки **не обязателен**,
   если есть поиск по журналу.

**Эффективность на вызов модели** меняет картину:

| Условие | Вызовов | Точность на вызов |
|---|---|---|
| A | 2 | 4,0 |
| **B (SCC)** | **3** | **67,0** |
| C | ~115 | 4,6 |

**По эффективности SCC выигрывает у поиска в 14 раз.** Если важна абсолютная
точность — поиск; если стоимость и время — SCC.

Разбор: [`_research/R-SCC-12_ABC_нужен_ли_SCC.md`](_research/R-SCC-12_ABC_нужен_ли_SCC.md).

**Чего SCC не делает.** Не сохраняет несжимаемые значения: хеши и дампы —
9 182 на входе → **0** на выходе. Это фильтр по силе смысла, а не дефект: у имени
файла есть структура, у хеша только энтропия. Модель не выдумывает отсеянное,
а ставит указатель.

## Состояния методологии

| Состояние | Разрешено | Запрещено |
|---|---|---|
| **В_РАБОТЕ** | редактировать методологию | любые работы по реализации |
| **ПРИНЯТ** | реализовывать | править без обращения к пользователю |

Если **хотя бы одна** методология в `В_РАБОТЕ`, реализация запрещена
**полностью**. Меняет состояние **только пользователь**. Отсутствие состояния —
не разрешение, а неизвестность (код 2).

## AGENTS.md: указатель, а не копия

В корне лежит [`AGENTS.md`](AGENTS.md) — **точка входа для агента**. Он подаётся
автоматически при каждом запросе и **не сжимается компакцией**: после неё
восстанавливается сам.

**Что внутри:** назначение проекта, правило «сначала методология — потом
действие», таблица «где что лежит / когда читать», **гейт состояний** с кодами
0/1/2, восемь инвариантов сжато, порядок контекста, запреты, бюджет.

**Тела методологий туда класть НЕЛЬЗЯ.** Вместе они занимают ~117 000 байт при
бюджете 65 536 (×1,8), а механизм при превышении **молча усекает** — агент
получит неполный текст, считая его полным.

**Контроль размера:**

```bash
python3 _engine/tools/check_agents_size.py         # проверить
python3 _engine/tools/check_agents_size.py --fix   # подставить числа
```

Проверяет размер, битые ссылки и наличие ссылок на все шесть методологий.
Коды: 0 норма, 1 нарушение, 2 файла нет.

**Главное правило файла:** если **хотя бы одна** методология в `В_РАБОТЕ` —
изменения в проекте **запрещены целиком**. Проверка:

```bash
python3 _engine/tools/check_state.py --gate
```

## Роли в контексте и доля удержания

| Слой | Роль | Сжимается |
|---|---|---|
| **`AGENTS.md`** | точка входа: базовые права и гейты агента по отношению к проекту, ссылка на методологии | **НЕТ** |
| **METHODOLOGY** | расширенные права агента, правятся **с согласия владельца** | **НЕТ** |
| Пересказ истории | рабочая память диалога (`retainRatio`) | да |

**Правило:** точные данные, которые обязаны дойти до модели дословно, кладутся в
`AGENTS.md` или методологию — **не в историю диалога**. Пересказ теряет точные
значения (88 % путей за цикл), но контракт агента при этом не теряется.

**`retainRatio = 0.16` принят как штатный.** Отношение — не плавный регулятор
точности, а **жёсткий порог**: при превышении компакция перестаёт запускаться
вовсе. При окне 1M доля 50 % требует истории сообщений **больше 495 904
токенов**, иначе сжимать нечего. Разбор —
[`_research/R-SCC-11`](_research/R-SCC-11_доля_удержания.md).
