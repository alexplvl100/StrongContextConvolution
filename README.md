# StrongContextConvolution

**SCC (Strong Context Convolution)** — свёртка сильного контекста: способ сжать
длинный контекст агента так, чтобы **ядро не терялось**, а факты не вымывались
поколениями пересказов.

Обычная компакция заменяет старую историю пересказом, и каждый следующий
пересказ теряет детали. Замерено на живой сессии (83 компакции, 114 ходов):

```
фактов в 1-й сводке:            129
сохранилось к 41-й сводке:        1  (1 %)
сохранилось к 83-й сводке:        0  (0 %)
```

SCC решает это иначе: **свёрнутое ядро помечается и больше не пересматривается**.
Повторная свёртка касается только свежей части, а ядро переносится дословно.

---

## Три уровня памяти

| Уровень | Что это | В контексте модели |
|---|---|---|
| **КОРОТКАЯ** | несжатый контекст в харнессе, растёт от чата | да, целиком |
| **СРЕДНЯЯ** | стак сжатых чанков, помещающийся в харнесс | да, стак + короткая |
| **ДОЛГАЯ** | архив чанков, вынесенный из контекста | **только инструкция**, содержимое — через Архивариуса |

Ключевой момент: контекст — это `[инструкция архива] + [стак] + [короткая]`.
При выносе в архив контекст **уменьшается**, хотя диалог продолжает расти.

Подробно: [`METHODOLOGY_MEMORY.md`](METHODOLOGY_MEMORY.md).

### Чего SCC не делает

**Не сохраняет несжимаемые значения.** Хеши, дампы, ключи: замерено 9 182 на
входе → **0** на выходе. Это не дефект, а работа фильтра: разделение проходит
по силе смысла. У имени файла есть структура — оно сохраняется; у хеша только
энтропия — он отсеивается. Модель при этом **не выдумывает** отсеянное, а
ставит указатель.

**Не возвращает чанки из архива.** Переход «долгая → средняя» отсутствует
принципиально: повторная свёртка чанков запрещена (инвариант 2).

## Состояния методологии: правка только по разрешению

У каждой методологии есть **состояние** — признак, можно ли её редактировать.
Меняет его **только пользователь**.

| Состояние | Разрешено | Запрещено |
|---|---|---|
| **В_РАБОТЕ** | редактировать методологию | **любые работы по реализации** |
| **ПРИНЯТ** | реализовывать, внедрять | **править без обращения к пользователю** |

**Контроль целостности:** если **хотя бы одна** методология в состоянии
`В_РАБОТЕ`, реализация запрещена **полностью** — методологии связаны, и
строить на подвижном основании нельзя.

```bash
python3 tools/check_state.py          # состояние всех методологий
python3 tools/check_state.py --gate   # код 1, если реализация запрещена
```

**Почему запрет машинный.** Харнесс может терять контекст. После потери он не
помнит решений и начинает **править связную методологию** — устраняя
«противоречия», которых нет. Правило, держащееся на «помни и не трогай»,
обходится тем самым сбоем, от которого поставлено.

**Отсутствие состояния — не разрешение, а неизвестность** (код 2).

Подробно: [`METHODOLOGY_STATE.md`](METHODOLOGY_STATE.md).

## HEAD: служебный раздел перед памятью

В самом верху контекста стоит **HEAD** — служебный текст, который **не является
памятью**: он не сжимается, не сворачивается и не уходит в архив.

```
┌──────────────────────────────────────┐
│ HEAD                                  │
│   1. РОЛЬ агента                      │
│   2. Инструкция Архивариуса           │
│   3. Инструкция CAS                   │
├──────────────────────────────────────┤
│ СРЕДНЯЯ ПАМЯТЬ: chunk_1 ... chunk_k   │
├──────────────────────────────────────┤
│ КОРОТКАЯ ПАМЯТЬ: несжатый диалог      │
└──────────────────────────────────────┘
```

**Зачем.** Роль агента лежит в первом событии потока. При сжатии она попадает
внутрь `chunk_1`, а при выносе в архив — **исчезает из контекста**. Измерено:
роль занимает **55,7 %** первого события и содержит **12 инструкций по
инструментам**. Без неё агент перестаёт пользоваться инструментами — это
деградация не памяти, а способности работать.

**Решение:** роль **извлекается из потока до сжатия** и переносится в HEAD.
Тогда архив не содержит дубля роли, а HEAD — единственное её место.

**HEAD изымается перед каждой свёрткой и возвращается после.** Это цикл, а не
разовая операция: иначе HEAD попадёт в чанк, уйдёт в архив и будет сжат при
следующей итерации.

**HEAD не проходит через CAS:** роль должна быть читаема всегда, а ссылка
`CAS?{хеш}?` требует доступа к базе. При потере базы роль стала бы нечитаемой.

Подробно: [`METHODOLOGY_HEAD.md`](METHODOLOGY_HEAD.md).
Исследование влияния: [`research/R-SCC-05`](research/R-SCC-05_HEAD_влияние.md).

## Доступ к точным данным — напрямую, минуя Архивариуса

В чанках встречаются ссылки `CAS?{хеш}?`. Это точные значения, вынесенные в
**CAS (content-addressed store)**: адрес вычисляется из содержимого,
восстановление побайтовое.

```python
from memory.cas import ContentAddressedStore
cas = ContentAddressedStore(dialog_dir / "cas.db")
cas.resolve_many(["a1b2c3d4"])     # -> {"a1b2c3d4": "/home/user/.../file.yml"}
```

**Обращение к CAS идёт напрямую, в обход Архивариуса — это обязательное
требование.** Архивариус агент с языковой моделью, а генерация пересказывает:
путь стал бы «похожим», хеш — «приблизительно верным». Точные данные обязаны
возвращаться дословно, поэтому путь к ним не проходит ни через одну модель.

Инструкция CAS ([`memory/cas_prompt.py`](memory/cas_prompt.py)) — **часть
HEAD**: она объясняет формат ссылки, порядок обращения и запрещает догадываться
о значении. Все три части HEAD стоят **перед** памятью:

```
┌──────────────────────────────────────────┐
│ HEAD — не сжимается, не уходит в архив     │
│   роль агента                            │
│   инструкция Архивариуса   доступ к архиву│
│   инструкция CAS           доступ к данным│
├──────────────────────────────────────────┤
│ СРЕДНЯЯ (чанки)                          │
├──────────────────────────────────────────┤
│ КОРОТКАЯ (несжатый диалог)               │
└──────────────────────────────────────────┘
```

При нуле ссылок промт не ставится вовсе — незачем занимать контекст.

## Транзитный режим: обработка без хранения

Для поставки, где хранение контекста запрещено, ядро умеет работать транзитом:
**принять контекст, преобразовать, отдать** — не создавая файлов.

```bash
# результат в stdout, на диск НЕ пишется
python3 core/scc_run.py stage3 WR.md WR_FILLED.md --to-stdout --no-ssc
```

| Флаг | Что делает |
|---|---|
| `--to-stdout` | результат в stdout, файл не создаётся; диагностика уходит в stderr |
| `--no-ssc` | без постфикса `(_SSC_)`: он нужен только для повторной свёртки, которой в транзите нет |

**Проверено:** полный цикл из трёх этапов запущен в пустом каталоге — после
прогона в нём **не появилось ни одного файла**. Измерено: 57 402 символа входа →
15 620 символов результата, ×3,7.

Цепочка поставки проходит только через `core/`: `memory/` в ней не участвует,
`cas.db` и `runtime/` не создаются.

## Живая проверка CAS

```bash
export ROUTERAI_API_KEY=...
python3 tools/test_cas_agent.py          # 4 сценария поведения агента
```

Агенту даются **инструменты доступа** (`resolve_many`, `restore`), которые
исполняются по-настоящему против базы. Обращение к CAS становится наблюдаемым
действием, а не рассуждением.

| Сценарий | Результат |
|---|---|
| Одна ссылка, значение есть | **ВЕРНО** — вызвал `resolve_many` |
| Ссылки нет в базе | **ВЕРНО** — сообщил, что значения нет |
| Три ссылки в чанке | **ВЕРНО** — разрешил одним вызовом |
| Провокация догадки | **ВЕРНО** — отказался угадывать |

Все четыре — с первой попытки. Отчёт:
[`research/R-SCC-04`](research/R-SCC-04_подключение_CAS.md).

**Тестирование коллизий нашло три дефекта**, один из которых приводил бы к
необратимой потере значений: прежний сдвиг адреса (`hash+1`) привязывал его к
порядку добавления. Теперь хеш **расширяется**, а адрес остаётся функцией
содержимого.
