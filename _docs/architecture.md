# Архитектура SCC

**Дата:** 2026-10-25

Схема компонентов и потоков данных. Правила поведения — в методологии,
здесь только устройство.

---

## 1. Компоненты

```
┌──────────────────────────────────────────────────────────────────┐
│ ЯДРО  (_engine/core/)                                                     │

│   prompts/         промты трёх этапов                             │

└──────────────────────────────────────────────────────────────────┘
```

## 2. Поток данных

```
чат
 │
 ├─► КОРОТКАЯ ПАМЯТЬ (short.py)
 │     растёт, объём > threshold_compress
 │            │
 │            ▼
 │      ЯДРО SCC (этапы I→II→III)     <- LLM (свёртка требует модели)
 │            │
 │            ▼  чанк
 │      CAS (cas.py)       <- без LLM, ПОСЛЕ ядра
 │            │  CAS?{хеш}? вместо повторов
 │            ▼
 │      СРЕДНЯЯ ПАМЯТЬ (medium.py)    <- без LLM
 │            объём стака > threshold_archivist
 │            │
 │            ▼
 │      ДОЛГАЯ ПАМЯТЬ (long.py)       <- без LLM
 │            стак заменяется инструкцией
 │
 └─► контекст модели = [HEAD: роль + Архивариус + CAS] + [стак] + [короткая]

     HEAD не сжимается и не уходит в архив (инвариант 8): он не входит в поток
     событий — разделение каналов выполняет конвертер журнала
     (--exclude-system, --system-out). См. METHODOLOGY_HEAD.md §3

ПРЯМОЙ ДОСТУП К ТОЧНЫМ ДАННЫМ (в обход Архивариуса):

     агент видит CAS?{хеш}?
        |
        +--> cas.resolve_many([...])  -> дословные значения
        |
        +--> Архивариус НЕ участвует: его пересказ исказил бы значение
```

## 3. Где проходит граница LLM

Это главное архитектурное решение: **языковая модель работает только в ядре**.

| Компонент | LLM | Почему |
|---|---|---|
| `scc_run.py` (этапы I–III) | **да** | свёртка смысла — задача модели |
| `scc_usability.py` | **да** | проверка пригодности задаёт вопросы |
| `cas.py` | нет | детерминированная обработка текста |
| `stack.py`, `medium.py`, `long.py`, `short.py` | нет | перемещение чанков — механика |
| Архивариус | **да** | разведка архива по запросу; **с CAS не работает** |
| Сборщик HEAD (`head.py`) | нет | изъятие и возврат HEAD — механика |

Граница проверяется тестом: `_test/test_memory.py` разбирает исходники
`_engine/memory/` через AST и падает при импорте LLM-клиента или сетевой библиотеки.

## 4. Почему ядро и память разведены

Ядро отвечает на вопрос «что было», память — «где это лежит». Смешение дало бы
два следствия, оба плохие:

1. **Память начала бы вызывать модель.** Перемещение чанков стало бы
   недетерминированным: один и тот же стак мог бы дать разный результат.
2. **Порядок чанков зависел бы от генерации.** Инвариант 5 требует, чтобы стак
   был детерминированной функцией от номеров, — с LLM в контуре это недостижимо.

Поэтому ядро возвращает чанк и **не знает**, куда он попадёт; память
перемещает чанки и **не знает**, как они созданы.

## 5. Иммутабельность и уровни

Уровень чанка (`medium` / `long`) хранится **не в файле чанка**, а в `chain.json`.

```
файл chunk_0001.json:   содержимое, метаданные  <- НИКОГДА не переписывается
chain.json:             n, level, file          <- level меняется при выносе
```

Это позволяет выносить чанки в архив, не трогая их содержимое. Инвариант 4
(чанк неизменяем) соблюдается буквально: файл не открывается на запись.

## 6. Контракт между компонентами

Единственный формальный контракт — схема чанка
[`_engine/core/schemas/chunk.schema.json`](../_engine/core/schemas/chunk.schema.json).

| Поле | Заполняет |
|---|---|
| `n`, `content`, `source_range`, `tokens_before`, `tokens_after`, `created_at` | ядро |
| `cas_refs` | CAS |
| `level` | память |

Разделение по заполняющим — причина, по которой схема лежит в `_engine/core/`, а не в
`_engine/memory/`: она описывает стык, а не одну из сторон.

## 7. Режимы отказа

| Сбой | Что происходит | Почему так |
|---|---|---|
| Свёртка не дала событий | код 1, повтор (до 3 попыток) | стохастика генерации |
| Свёртка оборвана по потолку | код 1, повтор с потолком ×1.5 | потолок не свойство модели |
| Неполное покрытие входа | код 1, повтор | модель самоограничивается |
| `chain.json` нечитаем | исключение `ChunkError` | молча начать заново = потеря порядка |
| Повторный номер чанка | исключение `ChunkError` | защита инварианта 4 |
| Коллизия хеша | сдвиг на следующий, лог в stderr | база подошла к пределу 8 символов |

**Общий принцип:** «не измерено» отличается от «чисто». Отсутствие данных даёт
код 2, а не 0 — унаследовано из методологии проекта SeverPact: ложное
срабатывание хуже отсутствия проверки.

## 8. Что не реализовано

| Часть | Состояние |
|---|---|
| Архивариус как агент | **нет**: есть только `long.read()` для него |
| Rollout в DSH | **заготовка** в `_rollout/deepseek-harness/` |
| Точный токенизатор | **нет**: эвристика, занижает на треть |
| Поведение при многих циклах архивации | **не проверялось** |
