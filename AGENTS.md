# SCC — точка входа для агента

**Проект:** StrongContextConvolution (SCC) — свёртка контекста агента без потери
ядра.
**Этот файл** — указатель на методологии, а не их замена.

---

## 1. ГЛАВНОЕ ПРАВИЛО

**При любом вопросе о поведении системы СНАЧАЛА прочитай методологию, потом
действуй.**

Не полагайся на память: методологии развиваются, и запомненное может расходиться
с текущим текстом. Если помнишь правило — проверь его в документе.

---

## 2. ЗАПРЕТ ПРИ СОСТОЯНИИ `В_РАБОТЕ`

**Верхнеуровневое правило, действует без напоминаний:**

> Если **хотя бы одна** методология имеет состояние `В_РАБОТЕ` —
> **любые изменения в проекте ЗАПРЕЩЕНЫ**. Не только правка методологии, а
> **вся реализация целиком**.

**Проверять ПЕРЕД работой:**

```bash
python3 _engine/tools/check_state.py          # таблица состояний
python3 _engine/tools/check_state.py --gate   # код возврата
```

| Код | Значение | Что делать |
|---|---|---|
| **0** | все `ПРИНЯТ` | реализовывать **можно** |
| **1** | есть `В_РАБОТЕ` | **СТОП**: изменения запрещены полностью |
| **2** | состояния нет | это **НЕ разрешение**, а неизвестность — выяснить |

**Правила:**

1. **`В_РАБОТЕ` хотя бы у одной — изменения запрещены целиком.** Методологии
   связаны; строить на подвижном основании нельзя.
2. **`ПРИНЯТ`** — реализовывать можно, но **тело методологии править нельзя**
   без разрешения пользователя. Разрешено обновлять только блок
   `**Реализация:**`.
3. **Отсутствие состояния (код 2) — не разрешение.** Требуется выяснить.
4. **Состояние меняет только пользователь.** Агент не переводит документы в
   `В_РАБОТЕ` сам.

## 4. КЛЮЧЕВОЕ, ЧТО НАДО ЗНАТЬ ДО ЧТЕНИЯ

**Порядок контекста:** `[HEAD] + [средняя память] + [короткая память]`.

**Два канала.** Через ядро SCC идёт **только юзерконтекст**. Системный контекст
(роль, правила) отделяется **на конвертере журнала**, а не изъятием после:
если роль попадёт в поток, ядро её сожмёт, и отменить это будет нечем.

**Восемь инвариантов** (полные — [`METHODOLOGY_MEMORY.md`](METHODOLOGY_MEMORY.md) §6):

1. Ядро SCC применяется **только** к короткой памяти.
2. Повторная свёртка чанков средней и долгой памяти **недопустима**.
3. Оборот памяти — **строго без LLM**, скриптами.
4. Чанк **неизменяем** после записи.
5. Стак чанков — детерминированная функция от номеров.
6. `chain.json` — **единственный** источник правды о порядке.
7. Архивариус — агент с LLM, только чтение архива.
8. **HEAD** — отдельная единица: не сжимается, не обрабатывается CAS, не
   уходит в архив.

## 5. ЧЕГО НЕ ДЕЛАТЬ

* **Не править методологии** без разрешения пользователя.
* **Не изменять проект**, если гейт вернул 1 или 2.
* **Не полагаться на память** о методологии — перечитывать.
* **Не дублировать числа** из документов в код: они устаревают молча.
* **Не менять тела методологий**, чтобы подогнать под код — выяснять причину
  расхождения.

## 6. БЮДЖЕТ ЭТОГО ФАЙЛА

**Файл подаётся агенту автоматически при каждом запросе и НЕ сжимается
компакцией.** Он восстанавливается после неё сам.

| | Значение |
|---|---|
| Бюджет механизма (`maxBytes`) | **65 536 байт** |
| **Текущий размер файла** | **7 909 байт** |
| Занято бюджета | **12.1 %** |
| Запас | 57 619 байт |

**Условие, которое надо соблюдать при правке:**

> **Держать размер ниже 65 536 байт.** При превышении механизм **молча
> усекает**: сначала отбрасывает файлы целиком, потом режет последний. Агент
> получит **неполный** текст, считая его полным.

**Тела методологий сюда класть НЕЛЬЗЯ:** вместе они занимают ~117 000 байт
(×1,8 от бюджета), и часть документов исчезла бы. Только ссылки.

**Проверка размера:**

```bash
wc -c AGENTS.md          # текущий размер
python3 _engine/tools/check_agents_size.py   # с проверкой бюджета
```
